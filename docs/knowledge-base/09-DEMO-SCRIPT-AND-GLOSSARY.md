## 1. Executive Summary & Demo Objectives

The live demonstration of **AEGIS** must conclusively prove that autonomous site reliability engineering does not require opaque "black-box" agents or unsafe execution privileges. Within **5 minutes**, the presenter must demonstrate the complete closed loop:
$$\text{Predict} \longrightarrow \text{Deploy} \longrightarrow \text{Monitor} \longrightarrow \text{Diagnose} \longrightarrow \text{Heal} \longrightarrow \text{Learn}$$

### Non-Negotiable Demo Invariants
1. **Never Hard-Code Demo Numbers**: The initial risk score of **65.0 ("Warn")** and post-incident score of **70.0 ("Blocked")** must be dynamically generated by active Python algorithms (`backend/sim/risk.py:95`), not hard-coded UI strings (`.agent/rules/05-honesty-real-vs-simulated.md`).
2. **Transparent Academic Honesty**: Explicitly label telemetry, pod metrics, and mock actuation as "simulated/emulator time," while demonstrating that the graph database, BFS decay, Tarjan cycle detection, contract diffing, LiteLLM reasoning, allowlist gates, and incident write-back are **100% real code** (`docs/06-REAL-VS-SIMULATED.md`).
3. **Safety by Construction**: Show that the LLM has zero execution privileges; it proposes ranked fixes which are strictly filtered by an allowlist, scored, snapshotted, and monitored with an automated rollback dead-man switch.

## 5. Definitive Alphabetical Technical Glossary (45+ Terms)

### 1. Actuator
- **Definition**: The guarded software component responsible for executing operational changes (restarts, pool scaling, rollbacks) against infrastructure services.
- **AEGIS Context**: In Phase 1, the actuator (`backend/executor/actuator.py:1`) updates in-memory repository telemetry. It enforces per-service concurrency locks (`_SERVICE_LOCKS`) and takes pre-change state snapshots.
- **Citation**: `backend/executor/actuator.py:1-42`.

### 2. Allowlist
- **Definition**: A strict security gate that rejects any proposed operation not explicitly declared on a pre-approved, non-destructive action list.
- **AEGIS Context**: Enforces that only `restart`, `scale_pool`, and `rollback` can be executed (`_ALLOWED_ACTIONS`). Parameter bounds are enforced by Pydantic models before execution.
- **Citation**: `backend/executor/allowlist.py:35-42`, `76-92`.

### 3. Anomaly Detection
- **Definition**: The algorithmic process of identifying statistical outliers or threshold breaches in time-series operational metrics.
- **AEGIS Context**: Evaluates whether latency, error rates, CPU usage, or connection pools deviate from baseline thresholds ($\text{latency} > 500\text{ ms}$, $\text{error\_rate} > 5.0\%$).
- **Citation**: `backend/monitor/health_checker.py:45-75`.

### 4. Blast Radius ($B$)
- **Definition**: The cumulative structural measurement of upstream services and client sessions impacted if a specific target service experiences degradation or breaking changes.
- **AEGIS Context**: Term $B \in [0, 100]$ in the composite risk formula, calculated via backward BFS traversal with exponential decay: $B = \min\left(100, \frac{\sum 0.75^{\text{hops}-1}}{C_{\text{cap}}} \times 100\right)$.
- **Citation**: `backend/sim/blast_radius.py:15-46`, `backend/graph/networkx_repo.py:164-200`.

### 5. Breadth-First Search (BFS)
- **Definition**: A graph traversal algorithm that explores all neighbor vertices at the present depth tier prior to moving to vertices at the next depth tier.
- **AEGIS Context**: Optimal $O(V + E)$ algorithm used in `repo.callers()` to discover upstream dependents tier-by-tier and apply discrete hop attenuation penalties.
- **Citation**: `backend/graph/networkx_repo.py:174-196`.

### 6. Caller Attenuation ($\gamma$)
- **Definition**: The mathematical discount factor applied to dependency impact as topological graph distance increases.
- **AEGIS Context**: Set to $\gamma = 0.75$ in `RiskConfig`. Direct callers (hop 1) receive weight $1.0$, secondary callers (hop 2) receive $0.75$, and tertiary callers (hop 3) receive $0.5625$.
- **Citation**: `backend/sim/config.py:22`, `backend/graph/networkx_repo.py:199`.

### 7. Chaos Engineering
- **Definition**: The discipline of experimenting on a software system to build confidence in its capability to withstand turbulent production conditions.
- **AEGIS Context**: Controlled synthetic fault injection module (`backend/chaos/faults.py`) injecting `pool_exhaustion`, `pod_crash`, `latency_spike`, and `cpu_spike`.
- **Citation**: `backend/chaos/faults.py:1-60`.

### 8. Closed-Loop Feedback
- **Definition**: A control architecture where output results are fed back into the system as inputs, modifying subsequent behavior.
- **AEGIS Context**: When an incident is resolved, `writer.py` persists an `Incident` node to the graph, automatically shifting future pre-merge risk scores by $+5.0$ points per incident.
- **Citation**: `backend/feedback/writer.py:29-60`, `backend/sim/risk.py:86-92`.

### 9. Composite Risk Score
- **Definition**: A single, normalized scalar metric in $[0, 100]$ evaluating the operational danger of merging a pull request.
- **AEGIS Context**: Calculated as $\text{Risk} = 0.35B + 0.25C + 0.20D + 0.20H$, mapped to verdicts: Approved ($< 40$), Warn ($40 \le \text{Score} < 70$), and Blocked ($\ge 70$).
- **Citation**: `backend/sim/risk.py:95-102`.

### 10. Context Isolation
- **Definition**: Sandboxing prompt input so an LLM reasons strictly over explicit graph data without hallucinating ungrounded infrastructure.
- **AEGIS Context**: `extract_context_node_ids()` extracts all valid service IDs from the 2-hop neighborhood. Proposals targeting IDs outside this set raise immediate validation errors.
- **Citation**: `backend/agent/rca.py:40-76`, `99-118`.

### 11. Contract Diffing ($C$)
- **Definition**: Comparing two API schemas (OpenAPI JSON/YAML) to detect backward-incompatible modifications.
- **AEGIS Context**: Evaluates deleted fields, altered data types, and added required fields. Assigns $C = 100.0$ if breaking changes exist, otherwise $0.0$.
- **Citation**: `backend/sim/contract_diff.py:30-125`.

### 12. Cypher
- **Definition**: The declarative graph query language utilized by Neo4j for pattern matching and graph manipulation.
- **AEGIS Context**: Parameterized queries in `queries.py` executing `MATCH (s:Service {id: $node})<-[:CALLS*1..3]-(c)` to retrieve callers in production mode.
- **Citation**: `backend/graph/queries.py:10-50`.

### 13. Dead-Man Switch (Health Watchdog)
- **Definition**: A fail-safe mechanism that automatically executes a corrective action (such as rollback) if a positive health confirmation is not received within a timeout.
- **AEGIS Context**: `health.py:wait_for_healthy()` polls target service health for 10 seconds post-remediation. If still unhealthy, `rollback.py` restores the pre-fix snapshot.
- **Citation**: `backend/executor/health.py:40-80`, `backend/executor/rollback.py:29-57`.

### 14. Decision Node
- **Definition**: A graph vertex representing an actuation choice made by the executor.
- **AEGIS Context**: Linked via `Incident -[:RESOLVED_BY]-> Decision -[:RESULTED_IN]-> Outcome` to maintain an immutable audit trail within the Knowledge Graph.
- **Citation**: `backend/feedback/writer.py:8-10`, `backend/graph/networkx_repo.py:240-255`.

### 15. Dependency Cycle ($D$)
- **Definition**: A circular chain of service dependencies ($A \to B \to C \to A$) that causes distributed deadlocks and prevents graceful boot sequences.
- **AEGIS Context**: Evaluated via Tarjan's SCC algorithm. If any component has $\text{size} > 1$, $D = 100.0$, contributing $20.0$ points to composite risk.
- **Citation**: `backend/sim/cycles.py:24-60`.

### 16. Directed Acyclic Graph (DAG)
- **Definition**: A directed graph structure containing no closed loops or circular paths.
- **AEGIS Context**: The desired state of microservice dependency topology. The presence of cycles breaks DAG properties and triggers risk penalties.
- **Citation**: `backend/sim/cycles.py:37-58`.

### 17. Elkjs / Dagre
- **Definition**: Hierarchical graph layout algorithms used to position nodes cleanly in tiered architectures.
- **AEGIS Context**: Used in the React frontend (`frontend/src/components/TopologyCanvas.tsx`) to layout the 54 microservice nodes by dependency tiers without overlapping edges.
- **Citation**: `docs/01-ARCHITECTURE.md#1-system-overview`, `frontend/package.json`.

### 18. Ephemeral Snapshot
- **Definition**: An in-memory or persisted capture of a service's configuration and telemetry state immediately prior to applying a change.
- **AEGIS Context**: Captured by `actuator.py:take_snapshot()` containing pre-change `pool_size` and `config_version` to enable instant rollback.
- **Citation**: `backend/executor/actuator.py:58-68`.

### 19. Fail-Closed Security
- **Definition**: A design principle where any failure, unhandled exception, or unexpected input results in access denial and execution halt.
- **AEGIS Context**: If allowlist validation fails, schema validation errors occur, or an unknown action is supplied, AEGIS refuses execution and marks the decision `refused`.
- **Citation**: `backend/executor/allowlist.py:80-92`.

### 20. Fallback Rules
- **Definition**: Deterministic, heuristic-based decision logic that executes when an external LLM is unreachable or times out.
- **AEGIS Context**: `fallback_rules.py` analyzes metric anomalies directly (e.g., latency high + pool 0 $\to$ propose `scale_pool`), returning valid `RCAResult` in $< 15\text{ ms}$.
- **Citation**: `backend/agent/fallback_rules.py:20-80`.

### 21. Graph Grounding
- **Definition**: Restricting LLM context and reasoning strictly to facts, relationships, and entities extracted directly from a Knowledge Graph.
- **AEGIS Context**: The core architectural principle of AEGIS. The prompt contains only verified 2-hop topological neighbors, eliminating generic LLM hallucinations.
- **Citation**: `backend/agent/context.py:40-85`, `AGENTS.md:1-10`.

### 22. GraphRepository
- **Definition**: The abstract interface decoupling business logic from underlying graph database implementations.
- **AEGIS Context**: Defines methods `get_topology()`, `callers()`, `incidents()`, `set_telemetry()`, and `add_incident()`, implemented by `NetworkXRepository` and `Neo4jRepository`.
- **Citation**: `backend/graph/repository.py:35-120`.

### 23. Historical Incidents ($H$)
- **Definition**: The count of production outages associated with a specific service over the past 30 days.
- **AEGIS Context**: Term $H \in [0, 100]$ in the risk formula: $H = \min(100, \text{incidents} \times 25.0)$. Contributes $20\%$ ($W_H = 0.20$) to the composite score.
- **Citation**: `backend/sim/risk.py:86-92`.

### 24. HMAC-SHA256
- **Definition**: A Hash-based Message Authentication Code using the SHA-256 cryptographic hash function to verify data integrity and authenticity.
- **AEGIS Context**: Outbound actuator requests are signed via `_sign_payload()` with header `X-AEGIS-Signature`. Target endpoints verify this to prevent unauthorized actuation.
- **Citation**: `backend/executor/actuator.py:45-54`, `backend/tests/test_executor.py:140-165`.

### 25. Ingestion-Lite
- **Definition**: A lightweight AST parser that inspects Kubernetes manifests or Docker Compose files to extract service dependency topology without full cluster deployment.
- **AEGIS Context**: Parses Online Boutique manifests (`docs/09-INGESTION-LITE-REFERENCE.md`) to extract `CALLS` and `CONNECTS_TO` edges with precision $\ge 90\%$.
- **Citation**: `docs/09-INGESTION-LITE-REFERENCE.md:1-50`.

### 26. LiteLLM
- **Definition**: A universal Python proxy library providing standardized OpenAI-compatible API calls across multiple LLM providers (Gemini, Groq, Ollama, Anthropic).
- **AEGIS Context**: Integrated via `call_llm()` to enable swapping between Google Gemini Free Tier, Groq, and local Ollama instances using environment variables.
- **Citation**: `backend/agent/llm.py:1-60`.

### 27. Mean Time to Recovery (MTTR)
- **Definition**: The average time required to diagnose and remediate a failed system or service.
- **AEGIS Context**: In AEGIS benchmarks, autonomous diagnosis and allowlisted remediation achieve simulated emulator MTTR of $< 10\text{ seconds}$ versus industry human baselines of 35 minutes.
- **Citation**: `docs/EVAL.md:40-60`, `.agent/rules/05-honesty-real-vs-simulated.md:10-15`.

### 28. Multi-Tenancy Isolation
- **Definition**: Partitioning application data and operations so multiple customers or projects operate securely on shared infrastructure.
- **AEGIS Context**: Every graph node, API route, and executor lock is scoped by `project_id` (e.g., `project_id="demo"`), verified in `test_multitenancy.py`.
- **Citation**: `backend/tests/test_multitenancy.py:1-75`, `backend/graph/networkx_repo.py:45-70`.

### 29. Neo4j Community Edition
- **Definition**: The open-source, Docker-deployable graph database engine optimized for storing connected data models.
- **AEGIS Context**: The primary production backend for AEGIS (`neo4j_repo.py`), activated by setting `GRAPH_BACKEND=neo4j` in `.env`.
- **Citation**: `backend/graph/neo4j_repo.py:20-80`, `deploy/docker-compose.yml:15-35`.

### 30. NetworkX
- **Definition**: A high-performance pure-Python library for the creation, manipulation, and study of the structure of complex networks.
- **AEGIS Context**: The zero-dependency default graph backend (`networkx_repo.py`), allowing AEGIS to run out-of-the-box on developer laptops and CI pipelines without Docker.
- **Citation**: `backend/graph/networkx_repo.py:1-391`.

### 31. OpenAPI AST Diffing
- **Definition**: Abstract Syntax Tree parsing and structural comparison of OpenAPI specification objects.
- **AEGIS Context**: Implemented in `contract_diff.py` to compare `old_schema` and `new_schema` dictionaries, identifying breaking API changes without LLMs.
- **Citation**: `backend/sim/contract_diff.py:30-115`.

### 32. Outcome Node
- **Definition**: A graph vertex recording the final execution status and measured recovery probability of an applied remediation.
- **AEGIS Context**: Created by `write_outcome()` after a decision reaches terminal status (`succeeded`, `rolled_back`, `failed`, `refused`).
- **Citation**: `backend/feedback/writer.py:29-60`.

### 33. PBKDF2-HMAC-SHA256
- **Definition**: Password-Based Key Derivation Function 2 using SHA-256, applying 100,000 hashing iterations with cryptographic salt.
- **AEGIS Context**: Used in `backend/security/encryption.py` to derive 256-bit AES encryption keys from master passwords for encrypting registered service secrets.
- **Citation**: `backend/security/encryption.py:20-45`.

### 34. Per-Service Concurrency Lock
- **Definition**: A synchronization primitive that guarantees only one remediation operation can execute on a specific microservice at any single point in time.
- **AEGIS Context**: `_SERVICE_LOCKS: dict[str, asyncio.Lock]` prevents race conditions and cascading oscillation if multiple faults trigger on `paymentservice` concurrently.
- **Citation**: `backend/executor/actuator.py:32-42`.

### 35. Predecessor Traversal
- **Definition**: Traversing directed edges in reverse direction (from callee backward to callers).
- **AEGIS Context**: In AEGIS, `CALLS` points `caller -> callee`. Blast radius discovery traverses predecessors (`G.predecessors(curr)`) to identify affected upstream clients.
- **Citation**: `backend/graph/networkx_repo.py:183-196`.

### 36. Pydantic v2 Schema Enforcement
- **Definition**: High-performance data validation and parsing using Python type hints, compiled in Rust.
- **AEGIS Context**: All API inputs, configuration parameters, and LLM outputs are validated via Pydantic models (`PRPayload`, `RCAResult`, `ValidatedProposal`), raising errors on invalid data.
- **Citation**: `backend/agent/schemas.py:1-60`, `backend/executor/allowlist.py:46-74`.

### 37. Rate Limiting
- **Definition**: Controlling the frequency of requests dispatched or received over a network interface.
- **AEGIS Context**: Defends API endpoints against denial-of-service and brute-force attacks; planned for Phase 2 hardening via `slowapi` token bucket filters.
- **Citation**: `docs/07-LIMITATIONS-AND-ROADMAP.md#31-known-technical-debt--vulnerabilities`.

### 38. React Flow (`@xyflow/react`)
- **Definition**: A customizable React library for building interactive node-based UIs and visual node graphs.
- **AEGIS Context**: The core visualization engine in `frontend/src/components/TopologyCanvas.tsx`, rendering interactive custom nodes, status halos, and mini-maps.
- **Citation**: `frontend/package.json`, `docs/01-ARCHITECTURE.md#1-system-overview`.

### 39. Rollback Automation
- **Definition**: Restoring a service's previous operational state when a newly applied patch fails post-deployment verification.
- **AEGIS Context**: `rollback.py:_rollback_emulated()` restores the pre-fix snapshot `pool_size` when the 10-second health check watchdog times out.
- **Citation**: `backend/executor/rollback.py:29-57`.

### 40. Root Cause Analysis (RCA)
- **Definition**: The systematic process of identifying the fundamental source vulnerability or hardware failure underlying a multi-service incident.
- **AEGIS Context**: Orchestrated by `backend/agent/rca.py:diagnose_incident()`, which combines graph context extraction, LiteLLM reasoning, and validation retries.
- **Citation**: `backend/agent/rca.py:122-160`.

### 41. Server-Sent Events (SSE)
- **Definition**: A server-to-client unidirectional streaming protocol using standard HTTP connections (`text/event-stream`).
- **AEGIS Context**: Streams diagnostic thought progression (`thought`, `cypher`, `candidates`, `result`) from FastAPI (`routes_heal.py:117`) to the React client in real time.
- **Citation**: `backend/api/routes_heal.py:117-142`.

### 42. Server-Side Request Forgery (SSRF)
- **Definition**: A web security vulnerability that allows an attacker to coerce a server-side application into dispatching requests to unauthorized internal destinations.
- **AEGIS Context**: Prevented by `backend/security/ssrf.py:validate_url_ssrf()`, which strictly blocks cloud metadata IPs (`169.254.169.254`) and private subnets.
- **Citation**: `backend/security/ssrf.py:25-110`.

### 43. Strongly Connected Component (SCC)
- **Definition**: A maximal sub-graph in a directed graph where every vertex is reachable from every other vertex within the sub-graph.
- **AEGIS Context**: Isolated via Tarjan's algorithm to detect circular architectural dependencies. Any SCC with $\ge 2$ nodes represents a fatal dependency cycle.
- **Citation**: `backend/sim/cycles.py:55-60`.

### 44. Synthetic Telemetry
- **Definition**: Programmatically generated metrics simulating system latency, error rates, CPU load, and connection pool saturation without real hardware infrastructure.
- **AEGIS Context**: Generated by `backend/chaos/telemetry.py` to create realistic test conditions for monitoring and RCA evaluation in Phase 1.
- **Citation**: `backend/chaos/telemetry.py:25-80`, `docs/06-REAL-VS-SIMULATED.md:10-30`.

### 45. Tarjan's SCC Algorithm
- **Definition**: A linear-time $O(V + E)$ depth-first search algorithm that partitions directed graphs into their strongly connected components using vertex index and low-link numbers.
- **AEGIS Context**: Powers cycle detection in `backend/sim/cycles.py:detect_cycles()`, ensuring pre-merge PR evaluations catch architectural circularities instantly.
- **Citation**: `backend/sim/cycles.py:24-60`, `docs/04-ALGORITHMS-AND-MATH.md#3-cycle-detection-tarjans-strongly-connected-components`.

### 46. Upstream Halo
- **Definition**: A visual concentric colored ring rendered around a microservice node on the topology canvas indicating impacted severity.
- **AEGIS Context**: Rendered in `frontend/src/components/TopologyCanvas.tsx` during PR simulation: red halos represent high impact ($\text{weight} \ge 0.8$), amber halos represent attenuated impact.
- **Citation**: `backend/sim/blast_radius.py:41`, `frontend/src/components/TopologyCanvas.tsx`.

### 47. Verdict Boundary
- **Definition**: The policy score thresholds determining whether a pull request is automatically approved, flagged for human review, or blocked.
- **AEGIS Context**: Defined in `backend/sim/config.py`: score $< 40$ is **Approved**, $40 \le \text{score} < 70$ is **Warn**, and $\text{score} \ge 70$ is **Blocked**.
- **Citation**: `backend/sim/config.py:30-35`, `backend/sim/risk.py:104-120`.
